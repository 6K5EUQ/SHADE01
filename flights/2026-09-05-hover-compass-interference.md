### 간섭의 크기

```
|B| 변동폭      0.206 G — 전체의 50.3%
수평 |B|        저전류 0.378 → 고전류 0.322 G  (14.8% 감소)

X축             −0.152
Y축             −0.098

방위에 미치는 영향:

```
전류 <10A :  자기 방위  24.5°  (std  5.5°)
전류 >45A :  자기 방위  −8.5°  (std 90.5°)
             → 33° 편향 + 산포 90°
```

**호버 전류가 44~48A 이므로 비행 내내 이 상태다.**

```

### 시점 — 완전 동시 (lag 0)

전류를 앞뒤로 밀며 `|B|` 와 맞춘 교차상관:

| 로그 | 최대 상관 lag | r |
|---|---|---|
| `09_17_46` | **+0.00 s** | −0.901 |
| `09_24_04` | −0.10 s | −0.717 |

`09_24_04` 의 −0.10초는 무의미하다 — **자력계 샘플 간격이 517 ms** 라 분해능 아래다.

**지연 0 = 순수 전자기 현상**(암페어 법칙). 전류가 흐르는 그 순간 자기장이 생긴다.
온도 드리프트·기계적 진동·센서 열화라면 반드시 지연이나 히스테리시스가 보인다.
이것이 전력선 간섭임을 한 번 더 확증한다.

## ❌ 2. 바람은 원인이 아니다 — 세 가지 독립 근거

조종자가 "바람이 많이 불었다" 고 했고, 실제로 불었다 (경사 최대 16.6°,
수평속도 최대 9.6 m/s). **그런데 자기장은 바람에 반응하지 않았다.**

### ① 바람 대리지표가 전부 0 에 붙어 있다

```
경사    vs |B|   −0.079 / −0.016
수평속도 vs |B|   −0.051 / +0.009
```

바람이 나침반을 흔든다면 기체가 기울 때 자기장이 흔들려야 한다. 안 흔들렸다.

### ② 자세를 고정해도 상관이 그대로다 (편상관)

| 경사 구간 | n | 전류−\|B\| |
|---|---|---|
| 0–3° | 562 | **−0.917** |
| 3–6° | 72 | −0.795 |

```
편상관 (경사 영향 제거 후):  −0.909 / −0.740
```

단순 상관 −0.906 → 편상관 −0.909. **전혀 줄지 않는다.**
바람이 만든 가짜 상관이었다면 여기서 무너졌어야 한다.

### ③ 가장 조용한 구간에서 오히려 더 강하다

수평속도 <0.5 m/s, 경사 <3° — 바람 영향이 가장 작은 정지 호버 구간만:

```
09_17_46:  n=362   전류-|B|  −0.951   ← 전체(−0.906)보다 강함
09_24_04:  n=223   전류-|B|  −0.863   ← 전체(−0.735)보다 강함
```

**바람이 잦아들수록 상관이 뚜렷해진다.** 바람이 원인이면 정반대여야 한다.

### 물리적 확증

`|B|`(자기장 세기) 는 **회전불변량**이다. 기체가 어떻게 기울고 돌든 지구 자기장
세기는 변할 수 없다.

```
yaw vs |B|   −0.152 / −0.173   ← 회전해도 거의 안 변함 (정상)
전류 vs |B|  −0.906 / −0.735   ← 전류에는 크게 반응 (비정상)
```

**변하면 안 되는 양이 전류에 따라 변한다.** 바람은 `|B|` 를 바꿀 물리적 경로가 없다.

### 바람의 실제 역할 — 증폭

바람은 원인이 아니라 **증폭기**다. 바람에 맞서느라 전류가 오르고, 전류가 오르면
간섭이 심해진다. `09_24_04` 가 바람이 더 셌고(경사 std 3.25 vs 1.54,
최대전류 80A vs 57A) 자기장 변동폭도 더 컸다(0.206 G vs 0.135 G).

> `09_24_04` 의 모터출력−\|B\| 상관이 −0.278 로 낮은 것도 여기서 설명된다.
> 바람 때문에 모터가 차동으로 움직여 **평균 출력**이 총 전류를 대변하지 못했다 —
> 모터출력 vs 전류 상관이 +0.945 → +0.593 으로 떨어진 것이 그 신호다.
> 그래서 이 로그에서는 **전류가 더 정직한 지표**이고 그 값이 −0.735 다.

## ❌ 3. UBEC·서보는 무죄 — 오늘 서보는 움직이지 않았다

조종자가 "전원선과 GPS 는 일부러 이격했다. UBEC 만 GPS 에 가까운데
오늘 서보 쓸 일 없지 않나" 라고 지적했다. **정확한 지적이었다.**

`09_24_04` 실측 (4296 샘플 전부 유효):

| 출력 | 값 | 변동 |
|---|---|---|
| MAIN1 우에일러론 | **1500 ~ 1500** | **std 0.00** |
| MAIN2 좌에일러론 | **1500 ~ 1500** | **std 0.00** |
| MAIN8 크루즈모터 | 1000 ~ 1000 | std 0.00 |
| MAIN5 UBEC | 신호 미사용 | — |

`actuator_servos` 도 전 채널 **정확히 0.0000, std 0.00000** — 엘리베이터·러더도 미동조차 없다.

당연한 결과다. `VT_ELEV_MC_LOCK=1` 로 MC 모드에서 제어면이 잠겨 있고 오늘은
고정익 전환이 없었다. **UBEC 는 거의 무부하였으므로 자기장 변동을 만들 수 없다.**

### 그럼 무엇인가 — 움직인 것은 모터 4개뿐

```
MAIN3 VTOL우후   1000~1911   std 103.1
MAIN4 VTOL우전   1000~1833   std 100.3
MAIN6 VTOL좌후   1000~2000   std 101.2
MAIN7 VTOL좌전   1000~1811   std 108.8
```

**오늘 전류를 소비한 것은 VTOL 모터 4개가 전부다.** 그 전류가 44~48A(최대 81A).

전원 주선을 이격했는데도 −0.9 가 남았다는 것은 **주선이 아닌 다른 경로**가
원인이라는 뜻이다. 남은 후보:

| 후보 | 근거 |
|---|---|
| **모터 상선(ESC→모터 3상)** | 주선을 떼도 각 모터 3상선은 암을 따라 뻗어 있다 |
| **ESC 자체** | 스위칭 전류가 크다 |
| **전류 귀환 경로** | +/− 가 다른 경로로 돌면 루프 면적이 커진다 |
| **프레임을 통한 전류 루프** | 루프가 프레임으로 닫히면 프레임 전체가 자기원 |

Z축 상관 −0.670 은 자기원이 나침반 **위/아래** 에 있음을 가리킨다.
GPS 를 마스트로 올렸다면 **바로 아래 동체의 ESC/배터리 구획**이 가장 유력하다.

### ⚠️ 은박지는 효과가 없다

| | 전기장 차폐 | **자기장 차폐** |
|---|---|---|
| 재료 | 도체 (알루미늄) | **고투자율 재료** (뮤메탈, 철) |
| 은박지 | ✅ 됨 | ❌ **거의 안 됨** |

알루미늄 비투자율 ≈ **1.00002** (진공과 사실상 동일) — 자기장이 그냥 통과한다.
게다가 우리 문제는 **DC 자기장**이라 도체 차폐가 의존하는 와전류가 생기지 않는다
(와전류는 자속이 변할 때만 생긴다). 알루미늄이 듣는 것은 고주파(ESC 스위칭
노이즈, RF)인데 그것은 지금 문제가 아니다 — lag 0 에 상관 −0.9 인 저주파 DC 성분이 문제다.

뮤메탈로 나침반을 감싸면 **지구 자기장까지 막혀** 나침반이 아무것도 못 읽는다.

**→ 은박지는 무게만 늘고 효과가 없다. 하지 마라.**

### 거리를 못 벌릴 때의 대안 (우선순위)

| 순위 | 조치 | 비용 | 예상 효과 |
|---|---|---|---|
| 1 | **+/− 선 트위스트, 루프 면적 최소화** | 0원, 30분 | **큼** |
| 2 | 지상 모터별 시험으로 범인 특정 | 0원, 10분 | 진단 |
| 3 | 내부 나침반(`CAL_MAG1_PRIO=0`) 살려 교차검증 | 0원 | 중간 |
| 4 | 전류 기반 보정 검토 (v1.17 지원 범위 확인 필요) | 0원 | 중간 |
| 5 | 경량화 / 프로펠러 대형화로 전류 자체 감소 | 큼 | 근본 |

🔴 **1번이 핵심이다.** 자기장은 전류가 아니라 **전류 루프 면적**에 비례한다.
`+` 와 `−` 를 꼬아 붙이면 자기장이 상쇄된다. **전원선을 GPS 에서 떼는 과정에서
`+` 와 `−` 를 서로 다른 경로로 돌려놓았다면, 이격이 오히려 루프 면적을 키워
역효과를 냈을 수 있다.** 흔한 함정이므로 반드시 확인할 것.

## 🟡 4. STAB → ALT/POS 전환 시 모터가 확 도는 이유

조종자 질문: "STAB 으로 모터 돌리다가 ALT 나 POS 넣으면 모터가 갑자기 확 돈다".

`09_17_46` 9.7초가 정확히 그 순간이다:

```
  t      M3    M4    M6    M7   평균  | 전류  | 스로틀 스틱
 9.50   1309  1466  1280  1439  1374 | 15.3A | -0.485
 9.75   1545  1698  1547  1701  1623 | 66.6A | -0.485   <<< 전환
10.00   1409  1436  1475  1490  1452 | 14.8A | -0.485
```

**스틱은 −0.485 로 미동도 없었는데** 모터 4개가 동시에 +250 유닛, 전류는
15A → 66.6A 로 **4.4배** 튀었다. 0.25초짜리 순간 펄스였다.

4개가 같은 방향으로 동시에 움직였다 = 자세 제어(차동)가 아니라 **집합 스로틀**이 올라간 것.

### 원인 — 스로틀 기준점이 모드마다 다르다

| 모드 | 스틱의 의미 | 스틱 −0.485 의 결과 |
|---|---|---|
| **STAB** | 스로틀 직접 지령 | 그대로 약 25% → **1374** |
| **ALT/POS** | **상승/하강 속도** 지령 | "고도 유지" → **호버 추력 필요** |

ALTCTL 진입 순간 컨트롤러가 고도 유지에 필요한 추력을 `MPC_THR_HOVER` 에서 가져온다.

```
MPC_THR_HOVER = 0.65      ← 65%
전환 직전 실제 출력 ≈ 0.25 ← 25%
                    40%p 차이가 그대로 모터로
```

전환 직후 `vz_sp` 가 0.00 → **+0.33** 으로 잡히며 컨트롤러가 개입을 시작하는 것도 로그에 보인다.

### 9/5 파라미터 변경이 이것을 1.6배 키웠다

**9/5 17:15 에 `MPC_THR_HOVER` 를 0.50 → 0.65 로 올렸다** (FC_CHANGELOG).
변경 자체는 옳았다 (FC 자체 추정값이 0.65). 그러나 부작용이 정확히 이것이다:

```
이전 0.50 → 스틱 25% 와 격차 25%p
현재 0.65 → 스틱 25% 와 격차 40%p    ← 점프 1.6배
```

**낮은 스로틀에서 전환할수록 점프가 커진다.** 지상에서 모터만 살살 돌리다
ALT/POS 를 넣는 것이 최악의 조건이다.

### 이미 호버 중이면 점프가 없다

```
09_24_04 @8.0s   전 1605 → 후 1571   점프 없음 (이미 호버 추력)
09_17_46 @9.7s   전 1374 → 후 1623   점프 249 (지상 저스로틀)
```

`MC_AIRMODE=0` 도 부차적으로 관여한다 — 낮은 스로틀에서 제한되던 자세 제어 권한이
전환 순간 되돌아오며 출력이 튄다.

### 대처

🔴 **지상/저고도에서 이 점프가 나면 기체가 갑자기 튀어오른다.** 66.6A 는 호버
전류(44A)를 넘어 순간 상승 가속이 붙는다. 사람이 가까이 있으면 위험하다.

- **스로틀을 호버 근처로 올린 상태에서 모드를 바꿔라.** 격차가 없으면 점프도 없다
- 지상 모터 시험 중이라면 **STAB 을 유지**하고, 모드 전환은 호버가 잡힌 뒤에
- `MPC_THR_HOVER` 를 되돌리는 것은 **권하지 않는다** — 0.65 가 실측에 맞고
  `MPC_USE_HTE=1` 로 비행 중 자동 보정도 된다. **조작 순서를 바꾸는 편이 안전하다**

## ⚪ 5. 광류·거리센서 — 이번 증상과는 무관

`EKF2_OF_CTRL=1`, `EKF2_RNG_CTRL=1`, `MPC_ALT_MODE=2` 가 켜져 있으나
**하드웨어가 없다.** 로그의 `rng_vpos`·`ev_hvel` innovation 이 비어 있어
융합 자체가 시작되지 않았다.

> 조사 도중 이것을 호버 불안정의 유력 원인으로 한 번 지목했으나, 로그를 보니
> 아니었다. 원인은 나침반이다. 설정 정리는 여전히 필요하지만 우선순위는 낮다.

## 자동비행했다면 무슨 일이 일어났을까

**오늘 미션을 걸었다면 실패했을 가능성이 높다.**

| 결과 | 근거 |
|---|---|
| 사각형이 회전·왜곡 | 기수 기준이 33° 틀어진 채 항법 |
| **코너마다 최대 10초 정지** | `MIS_YAW_TMT=10`, `MIS_YAW_ERR=12°` — **33° 오차는 12° 판정을 통과 못 한다** |
| 미션 77초 → 최대 117초 | 코너 4개 × 10초 |
| 최악: 위치 발산 | 요가 틀리면 EKF 수평속도 방향이 틀리고 Position 제어가 엉뚱한 방향으로 민다 |

산포 90° 상태에서 12° 안에 드는 것은 운에 맡기는 것이다.

수동 호버에서는 조종자가 눈으로 보고 스틱으로 잡았다. **미션에서는 아무도 안 잡는다.**

### 배터리도 빠듯하다

```
09_24_04:  443초에 5416 mAh  → 12.2 mAh/초
셀당 최저 3.64 V (BAT1_V_EMPTY=3.6 에 근접)
부팅 후 누적 9803 / 16000 mAh
```

미션 77초면 940 mAh 로 넉넉하지만, 요 문제로 코너마다 멈추면 117초 → 1430 mAh.
여기까지는 견딘다. 문제는 **RTL 이 겹칠 때** — 이미 9803 mAh 를 쓴 배터리면
`BAT_LOW_THR=15%` 도달이 현실적이고, 그러면 `COM_LOW_BAT_ACT=3` 으로 RTL 이 또 걸린다.

### 전류 81.2A — 오늘 최악 기록

```
>45A  284회, 누적 239.8초 (비행의 54%), 최장 연속 10.8초
>60A  12회
최대  81.2 A     (이전 기록 9/2 79.3A 초과)
```

XT90 연속 정격 45A 를 **비행 시간의 절반 이상 초과**했다.
그리고 이것이 나침반 간섭을 악화시킨다 — **악순환**이다.
