## 1. 🔴 나침반 간섭 — 역대 최악을 갱신했다

전류-자기장 상관이 **−0.95** (`08_13_03`). 9/5·9/9 의 −0.91 을 넘었다.

10편 중 **7편이 −0.7 이하**다. 그 결과가 FC 메시지로 반복됐다:

```
Preflight Fail: heading estimate not stable
```

**이것이 미션의 실질 장애물이다.** 미션은 heading 에 의존하는데, 전류가 흐르면
기수 추정이 흔들린다. 스위치 문제(§2)를 고쳐도 이게 남는다.

대책은 그대로다 — GPS 마스트 높이기, 전력선 이격·트위스트
([9/5 분석](2026-09-05-hover-compass-interference.md)).

## 2. ⛔ 미션 — 걸린 적이 없다

10편 전부의 `nav_state` 전환을 뽑았다. **`AUTO_MISSION` 이 한 번도 없다:**

```
STAB → ALTCTL → POSCTL → AUTO_RTL → AUTO_LOITER
```

`POSCTL`·`AUTO_RTL`·`AUTO_LOITER` 는 나오는데 미션만 없다.

### 원인 — CH6 가 988 에 안 갔다

| 편 | CH6 최소 PWM | 988 근처 샘플 |
|---|---|---|
| 10편 전부 | **1173** | **0개** |

```
988  = 슬롯1 Mission   ← 한 번도 도달 안 함
1173 = 슬롯2 Stabilized ← 오늘 최소값
1350 / 1520 / 2010 = Alt / Pos / RTL
```

2010(RTL)은 나왔으니 **SC/SF 래치는 동작한다.** Mission 쪽 조합(`SC위+SF`)만
안 쓰였다. 미션이 실패한 게 아니라 **시작조차 안 했다.**

### 별개로, 그날 저녁 미션 자체도 무효였다

세션 뒤(17:53경) 미션을 걸려 하자 FC 가 거부했다:

```
[CRIT] No valid mission available, refusing takeoff
[CRIT] Waypoint could not be read.
```

원인은 **세 점이 완전히 같은 축퇴 경로**였다 —
`02-hover-test.plan` 이 TAKEOFF·LOITER·LAND 를 모두 같은 좌표에 두고 있었다.
PX4 는 이동 거리가 0 인 미션을 `mission_state=1(NO_MISSION)` 로 거부한다.

좌표를 6m 씩 벌려 고친 뒤 `mission_state=2(NOT_STARTED)` 로 정상이 됐다.

⚠️ **다만 경로가 12.2m 로 매우 짧다.** `NAV_ACC_RAD=3` 이라 도달 반경이 3m 인데
웨이포인트 간격이 6m 다 — 미션이 순식간에 지나간다. LOITER 5초를 실제로 보려면
간격을 15~20m 로 늘리는 편이 낫다.

## 3. 진동 — 대체로 양호, 스파이크 하나

평균 3.8~7.2 로 어제(9/9, 3.1~3.5)보다 약간 높지만 **클리핑 0회**를 유지했다.

🟡 **`08_17_46` 에서 185.4 스파이크 하나.** 검증했더니:

```
220샘플 중 >30 인 것 1개 (t=70.0s)
p50 3.43 · p90 5.25 · p99 8.59
```

**단일 샘플**이고 전후가 평탄하다. 실제 진동이면 봉우리가 넓게 퍼진다 —
센서 글리치로 보이나 단정하지 않는다. **다음 비행에서 반복되는지 보면 갈린다.**

## 5. ✅ 링크 — 188m 까지 무결, 그리고 오해 하나를 풀었다

**`rc_lost` 10편 전부 0회.** 188m 에서도 조종 링크가 한 번도 안 끊겼다.

### 거리별 (188m 편)

| 거리 | 기체 RSSI | 노이즈 |
|---|---|---|
| 0~25 m | −62 dBm | 11 |
| 50~75 m | −72 | 9 |
| 100~150 m | −79 | 6 |
| **150~250 m** | **−81** | **6** |

🔴 **멀어질수록 노이즈가 내려간다.** 거리 상관은 **+0.83** 이다.

멀리 나간 구간이 곧 **높이 뜬 구간**(41~59m)이라 건물·나무가 사라진 것이다.
즉 **거리보다 장애물이 링크를 더 좌우한다.**

⚠️ 그래서 "188m 까지 안전하다" 가 아니라 **"고도가 있으면 188m 까지 안전하다"**
까지만 말할 수 있다. **저고도 원거리는 아직 시험하지 않았다.**

### 풀린 오해

이날 데이터로 **조종 링크 세기를 CRSF 없이도 읽을 수 있다**는 것이 밝혀졌다.
`input_rc.rssi` 가 100 고정이라 "값이 없다" 고 알고 있었는데, ELRS 백팩이
MAVLink `RADIO_STATUS` 로 88Hz 씩 보내고 있었다.
[규명 경위](../web/live/README.md#-조종-링크-세기는-crsf-없이도-온다-2026-09-12-규명)

이후 라이브 계기판과 로그 뷰어 「통신」 단에 반영했다.

## 6. 🔴 배터리 — 또 끝까지 썼다

```
부팅 후 누적 12916 mAh   (README 규칙: 10000 에서 새 편 시작 금지)
```

마지막 편(`08_26_41`)이 그 대가를 보여준다:

```
 52.8s  Low battery
128.3s  Low battery → Failsafe: Hold 5초
149.7s  Critical battery → Failsafe: Hold 4초
172.8s  Disarming denied: not landed
        Kill engaged
```

### failsafe 기준선 (실기 실측)

| 파라미터 | 값 | 동작 |
|---|---|---|
| `BAT_LOW_THR` | 0.15 | 15% — 경고 |
| `BAT_CRIT_THR` | 0.07 | 7% — **RTL** |
| `BAT_EMERGEN_THR` | 0.05 | 5% — 즉시 착륙 |
| `COM_LOW_BAT_ACT` | **3** | 동작 = Return |

`Hold 5초` 는 PX4 가 failsafe 전에 주는 **개입 시간**이다. 그 안에 스위치를
움직이면 취소된다.

## 7. 에어스피드 — 보정했으나 여전히 음수

편별 평균 **−1.0 ~ −4.5 m/s**. 정지·저속인데 음수다.

`SENS_DPRES_OFF` 를 −4.52 → −3.06 으로 바꿨는데, **정지 중 생압 실측이
−9~−15 Pa** 라 여전히 6~12 Pa 를 덜 뺀다.

GPS 대지속도<0.7 m/s 구간 514샘플의 생압 중앙값이 **−11.03 Pa** 였다.

⚠️ **QGC 자동 보정을 쓰는 게 맞다** — 손으로 넣으면 온도·고도 보정이 빠진다.
쿼드 비행에는 무관하고, [고정익 해제](../README.md#-고정익-사용-금지--쿼드-전용-2026-09-04)
전제 조건이다.

## 8. 로그 하나가 전송 중 깨졌다

`08_26_41`(9.0MB)이 토픽 **65개**만 읽혔다 — 정상 편은 88~101개다.
`battery_status`·`vehicle_imu_status`·`sensor_gps` 가 통째로 없어, 웹 뷰어에서
전력·진동·모터출력·GPS·센서불일치 **다섯 단이 사라졌다.**

파일 문제가 아니라 **MAVFTP 전송 손상**이다 — 5회 받아 md5 가 전부 달랐다.
`fcvote.py` 다수결로 복원해 **65 → 92개**로 되살렸다.

이 일로 sync 4단계에 [자동 검사](../FLIGHT-SYNC.md)를 넣었다.
