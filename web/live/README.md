# web/live — 실시간 비행 트래킹

지금 나는 기체를 브라우저로 본다. 한쪽은 계기(HUD), 한쪽은 흘러가는 차트다 —
[shade01.bewe.co.kr](https://shade01.bewe.co.kr) 의 로그 뷰어가 **끝난 비행**을
보는 것이라면, 이쪽은 **지금 이 순간**이다.

```bash
./qgc live on                   # 켠다 → http://localhost:4400
./qgc live always               # 켜고 + 부팅 때도 자동 (재부팅해도 산다)
./qgc live off                  # 끈다 (부팅 자동시작도 같이 뗀다)
./qgc live status               # 상태 + 링크 수신 여부
./qgc live on 14551             # QGC·브리지와 14550 이 겹칠 때 비켜서 켠다
```

`systemd --user` 로 돈다 — **터미널을 닫아도 살아 있다.** 비행 중에 창이 닫혔다고
화면이 죽으면 곤란하기 때문이다. 유닛은 처음 `on` 할 때 저절로 설치된다.

**`always` 는 `enable` + `linger` 를 둘 다 건다.** `--user` 유닛은 `enable` 만으로는
부팅 때 안 뜬다 — 로그인 세션이 없으면 유저 매니저 자체가 없기 때문이다. 둘 다
있어야 "재부팅해도 산다" 가 성립한다. `off` 는 `disable` 까지 하므로 **off 는 진짜
off** 다 (그래서 `always` 가 `on` 의 플래그가 아니라 별도 하위명령이다).

직접 띄우려면 (포그라운드, Ctrl-C 로 종료):

```bash
./web/live/live                 # http://localhost:4400
```

🔴 **읽기 전용이다. FC 로 아무것도 보내지 않는다.** ARM·모드변경·미션업로드는
이 페이지로 못 한다 — 조작은 QGC 로 한다. 근거는 아래 「상행이 없다」.

## 무엇이 보이나

**좌측이 HUD, 우측이 흘러가는 차트다** (2026-09-05). Mission Planner·QGC 의
글래스 콕핏 관용구를 따른다 — 인공수평의가 좌측 패널을 꽉 채우고 계기가 그
위에 겹쳐 얹힌다.

🔴 **지도는 뺐다** (2026-09-05). 비행 중에 보는 것은 위치보다 **추세**고,
백팩 AP 에 붙어 있으면 타일이 안 와서 회색 판이었다. 위치 정보는 HUD 의
홈거리·홈 방향 벅·기수가 대신 말한다. 우측은 로그 뷰어와 같은 차트가 쓴다.

| 영역 | 내용 |
|---|---|
| HUD 중앙 | 인공수평의(하늘/땅·피치 사다리·롤 호) + **ARMED / 모드 / 경고** |
| HUD 좌 테이프 | **대지속도 GS** (🔴 대기속도가 아니다 — 아래 참조) |
| HUD 우 테이프 | 고도 AGL(홈 기준) + **50m 펜스 천장선** + 지면대 + 상승률 리본 |
| HUD 상 테이프 | 기수방위 + 코스 마커(바람에 밀리는 각) + 홈 방향 벅 |
| 전류 밴드 | 전류 + 0~70A 막대 + **45 / 66.8A 기준선** + 60초 추이 |
| 상태 밴드 | GPS · EKF · 진동 3축 · RC |
| 숫자 스트립 | 전압(셀당 병기) · 소모 · 스로틀 · 상승률 · 홈거리 · WP · 진단 |
| 차트 | **흘러가는 시계열.** 고도·속도·전력 기본, 자세·진동·GPS·EKF 는 켜서 본다. 시간축은 「몇 초 전」 |
| 메시지 서랍 | FC 의 STATUSTEXT (`Sensor lost` 등). 접을 수 있다 |

### 이 화면이 지키는 규칙

- 🔴 **대기속도는 계기에 없다.** 이 기체 피토관은 정지 시 −4.7~−5.0 m/s 를
  읽는 고장 센서다(`SENS_DPRES_OFF=-4.52`). MP 는 좌측 테이프가 대기속도지만
  여기서는 **대지속도**이고, 테이프 머리에 `대지속도 GS` 라고 못박아 두었다.
  `d.airspeed` 는 스트립 **진단** 칸에 무채색으로만 남고 어떤 경고 판정에도
  안 들어간다. [고정익 금지](../../README.md#-고정익-사용-금지--쿼드-전용-2026-09-04)를
  푸는 전제 조건이 이 영점이다.
- 🔴 **색 예산.** 정상은 전부 무채색이다. `--bad` 는 지금 조치가 필요한 것에만
  쓴다 — 전류>60A, 전압<21.0V, 링크 끊김·데이터 정지, `vtol≠MC`, CRITICAL.
  정상 비행 내내 빨강이 켜져 있으면 진짜 위험할 때 안 튄다. (실제로 전류 기본색
  `--c-cur` 이 `--bad` 와 같은 `#f85149` 라 30A 에서도 새빨갰던 것을 고쳤다.)
- 🔴 **얼어붙은 계기는 자기가 얼었다고 말한다.** 링크가 끊기거나(`live=false`)
  링크는 살았는데 기체 데이터만 3초 이상 멎으면 HUD 전면에 프리즈 오버레이가
  덮인다. 멀쩡해 보이는 테이프가 옛 값을 가리키는 것이 가장 위험하다.
- 🔴 **없는 값은 안 그린다.** 기수(`hdg`·`yaw`)가 둘 다 없으면 0° 를 그리지 않고
  테이프를 흐리고 `방위 없음` 이라 적는다 — 가짜 0° 는 북쪽을 향한 것처럼 보인다.
  창 밖으로 나간 마커도 가장자리에 붙여 두지 않고 삼각형으로 바꾼다.
- **쿼드 전용 경고**: `d.vtol` 이 `MC` 가 아니면 HUD 중앙에 붉은 블록이 점멸한다.
  동시 발생 시 점멸은 **상위 하나에만** 붙는다.

### 안 그리는 값과 이유

`mission` (서버가 안 채운다 — `mav_live.py` 에 MISSION_ITEM 핸들러가 없다) ·
`cells` (PM08 DroneCAN 은 셀 전압을 안 줘 항상 1 이다. `volt/6` 으로 직접 계산) ·
`alt_msl` (기압계가 GPS 대비 −14m 인데 펜스·미션·RTL 이 전부 홈 기준 상대고도다.
나란히 두면 조종자가 매번 어느 쪽으로 판단할지 골라야 한다) ·
`radio_*` (SiK 관용구인데 이 기체 링크 3경로에 SiK 가 없다. `rssi` 가 없을 때만 대체) ·
`vz` (`climb` 과 부호만 다른 같은 값) · `rc_chan` (비행 전 점검 항목이지 계기가 아니다).

## 화면을 고쳤으면 자체검사를 돌려라

```
http://localhost:4400/_selftest.html
```

`?demo=1` 합성 피드를 iframe 으로 띄워 DOM 을 실측한다 — **FC 도 서버 데이터도
필요 없다.** 기하(배율 왜곡·잘림), 성능(노드 생성 0), 부호·스케일, 고장 센서 격리,
색 예산, 조건부 표시, 좁은 화면을 24개 항목으로 검사한다. **FAIL 이 0 이어야 배포한다.**

이 검사를 만들면서 실결함 셋이 잡혔다 — 정지 상태(`gs<1.5`)에서 `show(null)` 이
`TypeError` 를 던져 중앙 상태·스트립·상태밴드가 통째로 안 그려지던 것, 좁은 화면에서
HUD 가 제 부모를 113px 넘쳐 우측 패널이 밴드와 스트립을 덮던 것, 위의 전류 기본색 문제다.
셋 다 눈으로는 "그냥 좀 이상한데" 로 지나칠 수 있었다.

수동 확인용 합성 피드도 같은 파라미터를 쓴다:

```
http://localhost:4400/?demo=1                     # 전 계기 스윕
http://localhost:4400/?demo=1&roll=90&pitch=10    # 자세 부호 확인
http://localhost:4400/?demo=1&alt=50              # 펜스 천장선 정렬
http://localhost:4400/?demo=1&cur=61              # 과전류 색
http://localhost:4400/?demo=1&auto=1              # AUTO 일 때만 뜨는 WP 칸
```

## PC 별 구축 상태 (2026-09-05)

**4대 전부 가동.** 넷 다 합성 PX4 스트림으로 실제 디코딩까지 확인했다
(모드·ARMED·고도). 포트가 열린 것만 본 게 아니다.

| PC | 상태 | UDP 포트 | 왜 |
|---|---|---|---|
| `ku` | ✅ **항상** (부팅 자동) | **14550** | 비어 있다 |
| `rim3` | ✅ **항상** (부팅 자동) | **14551** | `shade-bridge` 가 14550 을 쥔다 (Tailscale 주소에 바인딩) |
| `rim` | ✅ **항상** (부팅 자동) | **14551** | QGC 가 14550 을 쥔다 (상주 지상국 — 22시간째 떠 있었다) |
| `gram-labtop` | ✅ 가동 (수동) | **14550** | 비어 있다. gram 앞에서 직접 설치 (SSH 는 여전히 막혀 있다) |

**`ku`·`rim3`·`rim` 은 `./qgc live always` 로 걸어 뒀다** (2026-09-05).
재부팅해도 저절로 뜬다. `gram` 만 수동이다 — 들고 나가는 노트북이라 항상 떠
있을 이유가 없고, SSH 가 막혀 원격으로 못 건다.

🔴 **14551 로 비켜 앉은 PC 는 브리지가 거기로도 보내줘야 한다.** `rim3` 은
자기 브리지가 루프백으로, `rim` 은 rim3 의 브리지가 Tailscale 로 보낸다 —
`pc_bridge.sh` 의 `TARGETS` 에 둘 다 적혀 있다. **이게 없으면 페이지는 켜져만
있고 패킷 0 이다.** 둘 다 실제로 그 상태였다.

새 PC 에 올릴 때 (한 번만):

```bash
cd ~/SHADE01
git pull
python3 -m venv .venv 2>/dev/null            # 이미 있으면 건너뛴다
.venv/bin/pip install -r web/requirements.txt
loginctl enable-linger $(whoami)             # 로그아웃해도 살아 있게
./qgc live on                                # 14550 이 막혀 있으면: ./qgc live on 14551
./qgc live status
```

⚠️ `.venv` 를 `--without-pip` 로 만든 PC (`ku` 가 그렇다) 는 `pip` 이 없다.
그때는 [ACCESS.md 의 휠 옮기기](../../gcs/ACCESS.md#pip--휠을-미리-받아-옮기기)를 쓴다.

⚠️ **`linger` 를 켜야 로그아웃 후에도 산다.** 안 켜면 SSH 를 끊는 순간 유닛이
죽는다 — `rim3`·`rim`·`gram` 은 처음에 `Linger=no` 였고 켜 줬다.

## 어디서 데이터를 받나

**UDP 14550 하나로 두 경로를 다 받는다.** 어느 쪽이든 그냥 켜면 된다.

| 경로 | 되는 PC | 방법 |
|---|---|---|
| **ELRS 백팩** (조종기 WiFi) | `rim3`, `gram-labtop` | `./gcs/qgroundcontrol/elrs-backpack` 로 AP 에 붙은 뒤 `./qgc live on` |
| **shade-bridge** (FC USB 직결) | 전부 (Tailscale) | 브리지가 도는 상태에서 `./qgc live on` |

⚠️ **`ku` 는 WiFi 장치가 없다** (유선 `enp3s0` 뿐). 백팩 AP 에 못 붙으므로
`ku` 에서는 브리지 경로로만 볼 수 있다 — [링크 구성](../../README.md#링크-구성--3-경로).

### 포트가 겹칠 때

QGC 나 `shade-bridge` 가 이미 14550 을 쓰고 있으면 **시끄럽게 죽는다.** 일부러
그렇게 했다 — `SO_REUSEADDR` 로 조용히 나눠 가지면 커널이 패킷을 한쪽에만 주어
QGC 와 이 페이지가 서로 프레임을 훔쳐 간다 (`mav_bridge.py` 와 같은 이유).

같이 쓰려면 **브리지가 로컬 14551 로도 같은 스트림을 보내야 한다.**
`pc_bridge.sh` 의 `TARGETS` 에 `127.0.0.1:14551` 이 들어 있는 이유가 이것이다
(2026-09-05 추가).

```bash
./qgc live on 14551      # 페이지는 14551 을 듣는다
```

🔴 **이 대상이 없으면 페이지는 켜져만 있고 패킷 0 이다.** `rim3` 에서 실제로
그랬다 — 유닛은 `active`, `enabled` 인데 화면은 빈 채였다. **서비스가 떠 있는
것과 데이터가 들어오는 것은 다른 말이다.** `./qgc live status` 의 `링크:` 줄로
확인한다. 브리지 쪽을 고쳤으면 `systemctl --user restart shade-bridge`.

## 상행이 없다 — 어떻게 보장하나

기체 FC 는 상행이 열려 있어서 `PARAM_SET` 한 줄로 ARM·모드변경이 들어간다
([README](../../README.md#2-pc-usb-직결-브리지----현재-가동중-rim3)). 브라우저에
붙는 페이지가 그 경로를 건드리면 안 되므로 **구조적으로** 막았다:

| 막은 방법 | 확인 |
|---|---|
| 소켓에 `sendto`/`send` 호출이 코드에 없다 | `grep -n "sendto" web/live/mav_live.py` |
| 파서를 `MAVLink(None)` 으로 만든다 — 출력 파일이 없다 | 실수로 `*_send()` 를 불러도 전송이 아니라 예외가 난다 |
| `mavutil.mavlink_connection()` 을 안 쓴다 | 그 래퍼는 하트비트를 자동으로 되쏜다 |
| HTTP 는 `do_GET` 만 있다 | POST 는 501 |
| HTTP 는 `127.0.0.1` 에만 바인딩 | `ss -tlnp \| grep 4400` |

**실측 (2026-09-04)** — 가짜 FC 를 세워 8초간 텔레메트리를 보내면서 페이지가
`/api/state`·`/api/reset` 을 두드리게 했다. FC 쪽으로 **돌아온 바이트 0**.

```

```

`./qgc live` 의 본체는 [`tools/live/livectl`](../../tools/live/livectl) 이고,
Claude Code 용 절차는 [`skills/qgc-live`](../../skills/qgc-live/SKILL.md) 다.

`chart.js` 와 `app.css` 는 **로그 뷰어의 것을 그대로 재사용**한다 (`web/public/`).
없으면 차트가 안 그려지므로 이 폴더만 떼어 옮기지 마라.

### 왜 폴링인가 (WebSocket 이 아니라)

서버가 "지금 상태" 하나만 들고 있고 화면은 그것을 5Hz 로 긁어 간다. 잠깐
끊겨도 다음 폴에서 저절로 복구되고, 되감을 상태가 없어 재접속 로직이 필요
없다. 텔레메트리 자체가 5Hz 라 더 자주 받아도 같은 값이 두 번 온다.

항적은 **안 받는다** — 지도를 뺐으므로 `?track=0` 으로 끈다. 40분 비행이면
점이 만 개가 넘어 폴 하나가 수백 KB 가 된다 (실측: 12초 만에 2978B → 1030B).
서버는 개수만 알려 준다.

## 알아 둘 것

🔴 **PX4 는 `ESTIMATOR_STATUS` 를 보낸다.** ArduPilot 의 `EKF_STATUS_REPORT` 가
아니다 — pymavlink `common` 에는 `EKF_*` 상수 자체가 없다. 그리고 그 값은
**분산이 아니라 비율(ratio)** 이다: **1.0 을 넘으면** 그 센서의 혁신 검사가
깨지고 있다는 뜻이다. 근거: `PX4-Autopilot/src/modules/mavlink/streams/ESTIMATOR_STATUS.hpp`

🔴 **`BATTERY_STATUS.voltages[]` 는 셀 전압이 아닐 수 있다.** PX4 는 셀 전압을
모르면(PM08 이 그렇다) **총 전압을 첫 칸에** 넣고, 65535 를 넘으면 65534 짜리
덩어리로 쪼갠다. 그래서 미사용 표식 **65535 만** 걸러야 한다 — 65534 까지
빼면 65.5V 를 통째로 잃는다. 실측 검증: 6S 셀별/총전압/쪼갠 값/14셀 전부 일치.

🔴 **차트 표본은 조기반환보다 위에서 뽑는다.** 시계열의 x축은 벽시계 시간이라
새 프레임이 없다고 표본을 건너뛰면 **링크가 끊긴 구간이 그래프에서 통째로
사라져** 끊긴 자국 없이 선이 이어진다 (실측: pollN 15 인데 trk.n 이 2 였다).
링크가 죽으면 null 을 넣어 선을 끊는다 — 없는 데이터를 지어내지 않는다.

🔴 **NaN 하나가 화면 전체를 끈다.** 파이썬 `json.dumps` 는 NaN 을 그대로
`NaN` 이라 적는데 그건 유효한 JSON 이 아니다. 브라우저의 `JSON.parse` 는 필드
하나 때문에 응답 전체를 거부하므로 고도·모드·전압까지 같이 사라지고 화면은
「서버 없음」을 띄운다. 서버는 멀쩡한데 화면만 죽는다.

실기에서 실제로 났다 (2026-09-05): `ESTIMATOR_STATUS` 의 vel·pos 비율이
EKF 수렴 전에는 NaN 으로 온다. `dumps_json()` 이 NaN·±Inf 를 null 로 바꾼다.

⚠️ **`curl` 로는 안 보인다 — 파싱을 안 하니까.** API 를 확인할 땐 반드시
파서를 거쳐라:

```bash
curl -s "http://localhost:4400/api/state?track=0" | python3 -m json.tool >/dev/null && echo OK
```

🔴 **chart.js 에 색을 넘길 땐 `cssVar()` 를 거친다.** `stroke` 를 **SVG 속성**
으로 쓰는데 속성값은 CSS 변수를 풀지 않는다. `var(--c-alt)` 를 그대로 넘기면
선은 그려지는데 색이 없어 화면에서 사라진다.

🟡 **백팩 AP 에는 인터넷이 없다.** 지도를 뺐으므로 이제 영향이 없다 —
차트·계기는 외부 자원을 안 쓴다.

🟡 **PX4 모드는 `custom_mode` 상위 바이트에 있다.** pymavlink 의 `mode_mapping`
은 ArduPilot 용이라 그대로 쓰면 엉뚱한 이름이 나온다.
